# E3-1 设计:共享目录协作协议

> 2026-10-18。PRD §3.3b(F-DIR-01~14)的协议层设计。原则:全部落在 Dart 扩展服务器(53318),**不动 packages/core**;文件内容走 53318 自有 HTTP 端点(经本机中转);身份与权限复用信任模型 + 源地址匹配。

## 1. 架构与角色

```
宿主设备(开放共享目录)                浏览设备
  共享目录配置(多目录/只读/可写)        目录树 UI(多设备)
  /api/anyshare/v1/dir/* 端点          HTTP 客户端 + 本地标签/备注库
        ↑ 请求携带 fingerprint(自述)          ↓ 下载→本机 / 上传→宿主 / 跨设备:下载+再上传(经本机中转)
        └──────── 明文 HTTP(53318,实验性,E2.3 加密覆盖)────────┘
```

- 宿主 = 任意平台(桌面为主,手机为前台服务保活);浏览方 = 任意平台
- 文件内容不经过 53317 v2 管线(该管线目标是固定接收目录,无法指向共享目录;改动它违反"不动 core")

## 2. 权限模型

请求体一律携带 `fingerprint`(自述)。宿主判定链(顺序):

1. **源地址必须匹配**:请求来源 IP == 收藏条目存储的 ip(与屏共同一硬化);不匹配 → 拒绝(403 `ip_mismatch`)
2. 未配对/未知设备 → 拒绝(403 `unknown`)
3. `blocked` → 拒绝;`temp` → 拒绝(F-DIR-08:临时设备永远只读——但"只读"也需要信任,故 v1 直接拒绝,仅同归属者与 full/limited 可访问)
4. 有效信任:`limited` → 只读;`full` → 按目录配置(只读/可写,且设备级「允许写入」开关,默认关);同归属者 → 按目录配置(可写目录默认可写)

**可写分档**(F-DIR-01/08):目录级 `writable` 配置 × 设备级 write 开关(仅 full 需要);同归属者不受设备开关限制。

## 3. 端点定义(全部 POST + JSON;53318)

| 端点 | 请求 | 响应 |
|---|---|---|
| `/dir/roots` | `{fingerprint}` | `{roots: [{id, name, writable, entryCount?}]}` — 仅返回该请求者可见的根 |
| `/dir/list` | `{fingerprint, root, path}` | `{entries: [{name, isDir, size, modified}], writable, truncated}` |
| `/dir/meta` | `{fingerprint, root, path}` | `{size, modified, isDir}`(冲突检查/刷新) |
| `/dir/download` | `{fingerprint, root, path}` | 二进制流(Content-Length;v1 不支持 Range,断点续传后续) |
| `/dir/upload` | `{fingerprint, root, path, name, size, onConflict: "rename"\|"overwrite"}` + 二进制体 | `{ok, finalName}`(写 `.tmp` + 原子改名) |
| `/dir/mkdir` | `{fingerprint, root, path, name}` | `{ok}` |
| `/dir/rename` | `{fingerprint, root, path, newName}` | `{ok, finalName}` |
| `/dir/delete` | `{fingerprint, root, path, trash: bool}` | `{ok}`(默认移入应用级回收站) |
| `/dir/trash/list` | `{fingerprint, root}` | `{items: [{id, name, originalPath, deletedAt, size}]}`(P2) |
| `/dir/trash/restore` | `{fingerprint, root, id, overwrite?}` | `{ok, path}`(P2) |
| `/dir/trash/purge` | `{fingerprint, root, id?}` | `{ok}`(P2) |

- `root` = 共享根 id(uuid);`path` = 相对路径(正斜杠)
- **实现说明(E3-2)**:`download`/`upload` 的元数据走**查询参数**(请求体/响应体为纯二进制流);其余端点 JSON 体
- 浏览类请求频繁:独立限速(600 次/分/IP,超限锁 30s)
- 错误码:`ip_mismatch / unknown / blocked / temp_not_allowed / read_only / not_found / conflict / invalid_path / too_large / rate_limited`
- **E3-2 遗留(后续批次)**:上传磁盘空间预检(507)与并发上传上限;收藏去重/upsert 与存储 IP 刷新(重配对时更新);写授权随收藏删除级联清理

## 4. 数据模型

**宿主(共享目录配置)**:持久化 `ls_shared_dirs`:
```json
[{"id": "uuid", "path": "/home/x/Photos", "name": "照片", "writable": false}]
```
**宿主(设备写入开关)**:FavoriteDevice 增字段 `allowWrite: bool = false`(仅 full 生效;迁移默认 false)。

**浏览方(标签/备注,本机个人标注,F-DIR-07)**:持久化 `ls_dir_annotations`:
```json
{"<fingerprint>:<rootId>:<path>": {"tags": ["重要"], "note": "打印三份"}}
```
不同步、不上传;删除/重命名后的孤儿标注保留(不主动清理,避免误删用户数据)。

**回收站**:`<root>/.anyshare_trash/<ISO时间>-<原名>` + 旁挂 `<...>.meta.json`(originalPath、deletedAt);列表时扫描该目录。v1 用应用级回收站(跨平台一致、可远端恢复);**偏离 PRD F-DIR-10 的"OS 回收站优先"措辞,理由:OS 回收站无跨平台统一 API 且不可远端恢复——PRD 按此修订**。

## 5. 关键流程

**浏览**:客户端对每设备调 `/dir/roots`(缓存)→ 展开时 `/dir/list`(逐层懒加载);空目录/离线/只读态由响应驱动。

**下载**:`/dir/download` 流式写入本机接收目录(或用户选择的位置);进度显示在浏览器 UI;>N 文件的多选下载 = 顺序队列。

**上传(含"从系统拖入")**:客户端先 `/dir/meta` 或本地列表判断重名 → 按 F-XFER-06 策略(rename/overwrite;「每次询问」= 客户端弹窗 F-DIR-14)→ `/dir/upload` 流式上传;冲突在服务端再次校验(竞态),`onConflict` 兜底。

**跨设备粘贴/拖放(E3-4)**:客户端编排「A 下载 → 内存/临时文件 → B 上传」;**经本机中转**,不建 A↔B 直连(v1);大文件用临时文件而非内存。进度合成一条(下载% + 上传%)。

**删除**:确认弹窗(客户端)→ `/dir/delete`(trash=true 默认)→ 宿主移入回收站;回收站管理页(P2)按 root 列出/恢复/清空。

**重命名/新建文件夹**:直接端点调用,成功后局部刷新(不整树刷新)。

## 6. 安全与防护

- **路径穿越**:服务端 `p.normalize()` 后校验无 `..`、非绝对路径、realpath 落在根内(处理符号链接指向根外的情况)→ `invalid_path`
- **符号链接**:列表不跟随(isLink 标记可选);realpath 校验兜底
- **明文风险**:指纹自述 + 源地址匹配为 v1 唯一防线(与屏共同款硬化);PRD 已标注实验性;E2.3 加密后并入
- **写入安全**:`.tmp` + 原子改名;同名竞态用 `rename` 策略时二次生成唯一名
- **资源**:单请求体大小上限(下载无上限流式;上传按 Content-Length 校验 + 磁盘空间预检,失败 507)

## 7. 与现有系统衔接

- 设置页「共享目录」分组(已占位):多目录增删、只读/可写、显示路径与状态
- 设备详情页:full 设备「允许写入」开关(F-DIR-08)
- 传输面板(F-XFER-16):E3 传输 v1 在浏览器内显示进度;并入全局面板作为后续增强
- 「发送到…」与目录树(F-DIR-09):E3-3 实现树+发送联动
- 标签筛选(F-DIR-12):E3-3 基于本机标注库

## 8. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| E3-2 后端 | 宿主端点(roots/list/meta/download/upload/mkdir/rename/delete)+ 权限链 + 路径防护 + 单测(穿越/权限/冲突/原子写) | curl/脚本端到端:两机读写往返、非法路径拒绝、只读拒绝 |
| E3-3 UI | 共享目录设置、多设备树浏览、双视图、预览、右键菜单、拖放、标签备注、排序/搜索/筛选、冲突弹窗 | 双机真机操作全流程;原型一致 |
| E3-4 跨设备 | 粘贴/拖放经本机中转 + 进度 | 双机 A→B 复制/移动 |
| E3-5 回收站 | trash 列表/恢复/清空 UI(P2) | 删除后可恢复 |
