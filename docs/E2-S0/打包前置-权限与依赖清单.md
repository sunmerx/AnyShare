# 打包前置:权限与依赖清单(双机验收实测收集)

> 2026-10-19 收集。来源:E3 双机验收 + Ubuntu 构建环境搭建的实机踩坑。
> 目标:制作 Windows / Linux / Android / macOS 安装包时,一次性覆盖所有运行时依赖、系统权限、防火墙与启动环境问题。
> 本文档为内部工程清单,按"打包时必须处理"与"开发环境已知坑"分级。

## 1. 网络端口与防火墙(两端都必须处理)

| 端口/协议 | 用途 | Windows | Linux (Ubuntu) | Android |
|---|---|---|---|---|
| 53317/tcp | 主协议 v2 HTTP(S)(v1 兼容) | 防火墙放行(实测首次运行自动弹窗;打包后签名稳定可预置规则) | `ufw allow 53317/tcp` **必须**(默认拒绝;实测不放行则对端完全无法访问) | 前台服务 + 网络权限 |
| 53317/udp | 组播发现(224.0.0.167 / ff12::fd3a:e420) | 同上 | `ufw allow 53317/udp` **必须**(不放行则设备列表互相扫不到;实测 Ubuntu 扫不到 Android 即此因) | 组播锁 + 网络权限 |
| 53318/tcp | AnyShare 扩展控制面(pair/dir/screen/trust) | 放行 | `ufw allow 53318/tcp` **必须** | 同上 |
| 53319/udp | 屏幕共享数据面(E-2) | 放行(接收方向) | `ufw allow 53319/udp` **必须** | 待 E2.4 |
| 53318 出站 | 客户端方向(浏览目录/投屏发起/配对) | 出站默认放行 | 出站默认放行 | — |

**打包动作**:
- Windows:安装时写防火墙规则(程序路径规则,Inno Setup `netsh advfirewall firewall add rule`);或首次运行引导用户确认。
- Linux:`.deb`/AppImage 无法自动改 ufw(需 root),安装后首次启动引导检测 + 一键复制 `ufw allow` 命令(或文档说明)。检测方法:尝试自连 53317/udp 组播收不到对端提示。
- Android:组播 + 前台服务权限按 LocalSend 上游既有方案。

### 构建环境(仅 CI/开发机,不进产物)

- Windows 构建:中文代码页下 connectivity_plus 触发 C4819 → 需 `CL=/utf-8`。
- Ubuntu 构建(本次为无 sudo 用户态方案,打包机可用正常 apt):
  - 系统包:cmake、ninja-build、pkg-config、clang、ld(binutils)、libnotify-dev、libayatana-appindicator3-dev、libgtk-3-dev

  - 坑:Flutter linux `dart_build` 需要真 clang(伪造 gcc 别名过不了身份校验)

## 3. 启动会话环境(SSH/服务方式启动 GUI 应用时的坑)

| 环境变量 | 缺失后果 | 说明 |
|---|---|---|
| DISPLAY=:0 | 无 GUI | XWayland |
| XAUTHORITY=/run/user/1000/.mutter-Xwaylandauth.* | Rust 接收窗口 `XOpenDisplay failed`(实测) | GNOME Wayland 会话的 X 授权文件,文件名随会话变化 |
| WAYLAND_DISPLAY=wayland-0 + XDG_RUNTIME_DIR=/run/user/1000 | GTK 无法走 Wayland;winit 无法创建原生 Wayland 窗口 | 会话内启动(终端/自启)自动具备 |
| DBUS_SESSION_BUS_ADDRESS | 通知/托盘异常 | 会话内自动具备 |

**结论**:桌面安装包按"会话内启动"(autostart .desktop / systemd --user)即可规避;若做 SSH/服务启动支持,需从会话进程读取以上变量(参考本次启动脚本)。

## 4. 应用内权限/授权链(已实现的检查,打包时确认文案与引导)

- `/dir/*` 与投屏控制面:对端需**收藏本机**(访问门),可写目录还需**设备写授权**;错误码已 i18n(unknown/ip_mismatch/blocked/...)。
- 投屏信任分档:temp 直接拒;limited 弹确认;full/同归属者免确认(D2 裁决)。
- 投屏地址:数据面 IPv4-only,已改为取 IPv4 通道地址(仅 IPv6 设备按钮禁用并提示)。
- Android:相机权限(扫码配对);存储/通知权限沿用上游 LocalSend 方案。
- macOS(未构建):共享目录需 security-scoped bookmark 持久化(E3-3a 记账),投屏接收未实现——macOS 打包时统一处理。
- Android 宿主共享目录:API 27+ SAF content:// 根不可用于 `/dir/*`,入口已门控;若支持需 SAF 适配通道(记账 L6)。

## 4.5 性能与构建档位(验收/发布必读)

- **必须用 release 构建做性能验收**:debug 构建下 Rust 侧 BGRA 转换每帧 178ms(2880x1800),release 仅 20ms——差 8.6 倍,会表现为"只有 6fps、极度卡顿"的假故障(本项目已实际踩坑)。
- 投屏诊断开关(环境变量,均可留空):
  - `ANYSHARE_DECODER=ffmpeg` + `ANYSHARE_FFMPEG_PATH`:强制 ffmpeg 解码(vaapi 非 1080p 灰帧临时绕行)
  - `ANYSHARE_FRAME_DUMP=/path.ppm`:接收端落盘最后解码帧(验收诊断)
  - `ANYSHARE_AUTOSHARE_IP=<IPv4>`:kDebugMode 下启动 4 秒后自动发起投屏(调试用)
- 发送端逐秒日志含 fps/码率/编码耗时/采集元数据计数(含光标),stderr 输出。

## 5. 数据迁移/兼容坑(打包影响)

- 偏好文件 `settings.json`:外部工具改写会把 double 写成 int(如 900.0→900),`SharedPreferences.getDouble` 抛 `int is not subtype of double` 直接崩在启动(preInit)。**任何版本迁移/脚本改动必须保留小数写法**;或应用侧加固读取(后续建议:getDouble 容错)。
- 旧版 LocalSend 数据目录迁移:Windows `%APPDATA%\LocalSend` → `%APPDATA%\AnyShare`(已有 `_windowsLegacyFile` 兼容)。
- Linux 偏好目录:`~/.local/share/io.anyshare.app/shared_preferences.json`(打包脚本/卸载脚本注意保留)。
