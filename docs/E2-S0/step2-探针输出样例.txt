# Step 3 验收样例(2026-10-17):VFR 门控 + 编码器探测

## ss-probe --vfr 静止场景(8s)

```
t=  2s frames=43   idle=0    dirty=50  (258.7% area) ... vfr_enc=27   kf=1
t=  3s frames=43   idle=0    dirty=48  (258.9% area) ... vfr_enc=29   kf=0
```

结论:内容连续变化时,~43-56 原始帧/秒被门控收敛到 ~27-31 编码/秒(帧率上限与无效帧合并生效);174 次速率合并、21 次指针-only 帧被跳过;关键帧每 ~2s(6 个/12s ✓)。单元测试 6 项全绿(静止/指针/突发合并/关键帧节奏/心跳/首次关键帧)。

# Step 4 验收样例(2026-10-17):全链路编码(capture→VFR→NV12→H.264)

## release 构建,AMD 硬件编码器,1080p,8s

```
encoder selected: AMDh264Encoder (input NV12, bitrate 6000 kbit/s, keyframe-force supported: true)
t=  7s frames=50   idle=0    dirty=61  (307.8% area) ... vfr_enc=30   kf=1 enc=30 avg_ms=6.9 kbps=6888 enc_kf=1

summary: 398 acquire iterations, frames=398 idle=0 (0.0% idle), access_lost_rebuilds=0
vfr summary: encoded=244 keyframes=4 skipped=154 (static=0, rate_limited=154)
encode summary: encoder=AMDh264Encoder frames=244 keyframes=4 avg_encode_ms=6.40 total_out=6.46 MiB
```

- **试编仲裁**:候选链 [硬件 AMDh264Encoder ×2 → 软件 H264 Encoder MFT],第一个试编通过者获胜(AMD 硬件)
- **性能**:release 6.40ms/帧(含 BGRA→NV12 转换 + MFT),1080p 实时余量 >2x;debug 构建 94ms(未优化转换),证明性能在转换与构建配置而非编码器
- **码流验证**:`ffmpeg -i dump.h264 -f null -` 全量解码通过(注入 MF_MT_MPEG_SEQUENCE_HEADER 后)
- **VFR**:154 次合并、关键帧 2s 节奏;duration 用实际帧间隔,空闲后首帧打 discontinuity 标记
- 关键工程坑(全部实测踩过):异步 MFT 需 `MF_TRANSFORM_ASYNC_UNLOCK` 解锁(否则 SetInputType 报 0xC00D6D77);解锁后**仍必须走事件泵**(NeedInput 才能喂入、HaveOutput 才能取流);**编码器要求调用方提供输出样本**(NULL 报 E_INVALIDARG);**SPS/PPS 在输出类型属性里**不在码流里,须提取注入
