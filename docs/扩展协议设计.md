## 1. 扩展通告(discovery 兼容注入)

> **⚠️ 2026-10-12 实施修订:本节暂缓,改用 §1a 探测机制。** 实施时核实:组播通告 JSON 在 Rust 侧由定长结构 `MulticastMessageV2`(serde)序列化,HTTP register 走 FRB 定长结构 `RegisterDto`——注入 `as` 字段需改 Rust + 重跑 FRB codegen,违背"Rust core 不动、rebase 成本归零"原则。`as` 字段保留为"阶段二候选"(若未来向上游提 PR 一并实现)。

v2 组播/HTTP 通告 JSON 中新增**单字段** `"as"`(AnyShare 扩展描述,LocalSend 客户端解析 JSON 后忽略未知字段):

```json
{
  "v": "2.2", "alias": "My Phone", "deviceModel": "Pixel 8",
  "fingerprint": "a3b1…", "port": 53317, "protocol": "https", "download": true,
  "as": { "ext": 1, "eport": 53318, "owner": "张三" }
}
```

| 字段 | 说明 |
|---|---|
| `as.ext` | 扩展协议版本,当前 1 |
| `as.eport` | **AnyShare 扩展服务器**(Dart 实现)端口,默认 53318;0 = 未启用 |
| `as.owner` | 归属者显示名(可选) |

**归属者身份**(ownerId)不在通告中明文广播(局域网隐私);经扩展服务器配对/查询时在 TLS 内交换。

## 1a. 探测机制(2026-10-12 实施方案,替代 §1)

AnyShare 实例通过**按需探测**互相识别:对任意已发现设备(详情页/配对入口),Dart 侧直接 `GET http://<ip>:53318/api/anyshare/v1/capabilities`(2s 超时)——应答即 AnyShare,失败即纯 LocalSend(端口未开,快速失败)。通告零改动,LocalSend 完全无感知。

**端口策略**:固定 53318,绑定失败则扩展功能停用(记日志)——不做顺延,否则探测方无从发现。v2 通告落地后可由 `as.eport` 携带实际端口。

## 2. 扩展服务器(AnyShare Extension Server)

> **⚠️ 2026-10-12 实施修订:首版为纯 HTTP + SAS 绑定,TLS 后置。** 理由:配对密钥交换的 MITM 防护由 SAS 6 位码目视比对承担(码绑定 transcript,中间人必然导致双端码不一致);配对流量仅数 KB 且仅配对瞬间存在;复用 Rust 临时证书需暴露 PEM 或引入 Dart 侧自签证书设施,成本与收益不匹配。归属者名/ID 仅在配对报文中交换,无未授权读取面(`capabilities` 仅含展示别名与归属者显示名,与通告等价)。

- 形态:**Dart 内嵌 HTTP 服务器**(dart:io `HttpServer`,主 isolate;配对流量远低于"重网络"阈值),端口 53318;随 app 启停(init 时启动)。
- LocalSend 客户端不会连接此端口(它们不认识 `as` 字段)→ **Rust core 与 53317 主服务完全不动**;rebase 成本归零。
- 路由前缀 `/api/anyshare/v1/`:

| 端点 | 方法 | 用途 |
|---|---|---|
| `/capabilities` | GET | 扩展能力:`{ext:1, sas:true, fingerprint, alias, ownerName}` |
| `/pair/register` | POST | SAS 配对注册:`{alias, fingerprint, eph(b64), port, https}` → `{session, code, eph, alias, ownerName, fingerprint}` |
| `/pair/confirm` | POST | 完成配对:`{session, ownerId, ownerName, alias}` → `{ok, ownerId, ownerName, alias, fingerprint}`;中止走本地 UI(码不一致) |

密码学:X25519(ephemeral)+ HKDF-SHA256,码 = OKM 大端整数 mod 10^6,transcript = `session ‖ sort(fingerprintA, fingerprintB)`(RFC 7748 向量单测锁定:`app/test/unit/util/sas_test.dart`)。`/pair/*` 按来源 IP 限速(5 次/分,超限锁 60s);pending 会话 5 分钟 TTL、单活跃(409 busy)。

## 3. 信任模型落地(数据与判定)

### 3.1 存储扩展(shared_preferences,不引入 SQLite)

`ls_favorites`(现有:`[{fingerprint, alias}]`)迁移为 `ls_trusted`:

```json
[
  {
    "fingerprint": "a3b1…",          // 信任锚(mTLS 证书 SHA-256,继承 favorites 语义)
    "alias": "My MacBook",
    "ownerId": "0d7e…",              // 配对时经扩展服务器交换
    "ownerName": "张三",
    "trustLevel": "limited",         // temp | limited | full
    "maxFileSize": 524288000,        // 字节;0 = 不限
    "quotaMode": "percent",          // none | absolute | percent
    "quotaValue": 2000,              // absolute:字节;percent:万分比(2000=20%)
    "favorite": true                 // 兼容旧"收藏"语义(置顶显示)
  }
]
```

迁移:启动检测旧 `ls_favorites` → 一次性导入 `ls_trusted`(`trustLevel: temp`,等价旧行为:收藏 = quickSaveFromFavorites 自动接收 → 我们映射为 `full`?**裁决点**:旧收藏设备映射为 `full`(行为连续)或 `temp`(更保守)→ 默认取 `full` 保持上游用户体验连续,记入验收记录)。
本机归属者:`ls_owner_id`(UUID,首启生成)+ `ls_owner_name`(用户设置)。

### 3.2 判定链(插入点:receive_controller.onPrepareUpload ③ 前)

```
senderFingerprint = event.certFingerprint
0. 黑名单(未来扩展)                       → 自动拒绝
1. 无信任条目(未配对)                     → 原版行为(PIN 已在 Rust 侧校验;弹 ReceivePage)
2. trustLevel=full 或 ownerId==本机 ownerId → quickSave=true(免确认,无限制)
3. trustLevel=limited                      → 校验 maxFileSize/quota:
     超限 → 自动拒绝会话 + 本地 toast("超出限额") + 历史记录
     未超 → quickSave=true
4. trustLevel=temp                          → 自动接收(2026-10-14 产品裁决:配对=接收方一次性确认,已配对设备不再逐次弹窗;等级仅决定限额是否生效)
配对完成通知:2/3 级接收完成已有系统通知(上游 quickSave 路径自带)→ 裁决-3 的"完成会提示"天然满足
```

配额已用量:按 fingerprint 聚合 `ls_receive_history` 条目 fileSize(启动时懒加载缓存,接收完成事件增量更新;删除历史扣减)——与 DDD 3.2 配额缓存设计同构,存储介质改为 SP。

### 3.3 配对 UI 动线(新增)

配对入口:设备卡片长按/详情 →「配对」;AnyShare 端检测对端 `as` 字段 → 有:SAS 流程(双端显示 6 位数字→双确认→选择「临时传输 / 加入信任列表(+等级+限额)」);无(纯 LocalSend):提示"对方设备不支持 AnyShare 配对,可继续用 PIN 方式传输",并允许本地单向收藏(旧行为)。

## 4. 与 LocalSend 客户端互操作矩阵

| 发送端 ↓ \ 接收端 → | AnyShare | LocalSend |
|---|---|---|
| **AnyShare** | 全功能:扩展通告+SAS+信任分级+限额 | v2 原版:PIN/确认(如对端开了自动接收则直接收) |
| **LocalSend** | v2 原版:PIN/确认/quickSave(对 AnyShare 无感知);不识别 `as`/扩展端口 | v2 原版 |

## 5. 阶段二候选(需动 Rust,暂缓,登记不实施)

- prepare-upload 响应的 `FILE_TOO_LARGE / QUOTA_EXCEEDED` 结构化错误体(现方案:Dart 自动拒绝,发送端见"已拒绝");
- 通告字段提升为 v2.3 正式可选字段(向上游提 PR 的形态);
- 归属者密码学绑定(归属者密钥签名 owner 声明)。

动 Rust 的重估条件:阶段一上线后用户反馈"拒绝原因不透明"占比高,且该期 rebase 成本可接受。

## 6. 开放点(实施时定)

1. `ls_favorites` 迁移映射:`full`(行为连续,默认)vs `temp`(保守);
2. 扩展端口默认 53318 与 AnyShare 旧自研端口撞车问题不存在(fork 已定 53317 为主),但需防其他应用占用——占用顺延逻辑复用上游 port 处理;
3. `/trust/query` 是否首版实现(发送前提示"对方会自动接收"很加分,但可后置)→ 首版仅实现 capabilities + pair(**已落地**,2026-10-12)。
4. (新增,2026-10-14 裁决修订)配对成功双方默认落 `temp`;**已配对设备传输一律自动接收**(temp/full 行为一致,等级仅决定 limited 限额是否生效),详情页可调/可拉黑。
5. (新增)`/pair/confirm` 到达而本地未按"码一致"时,响应方仍落库(temp):confirm 是发起方完成信号,本地"码不一致"只在 UI 层 abort 后续交互。
