## 1. 项目是什么

**AnyShare**:基于 LocalSend(Apache-2.0)fork 的跨平台局域网文件互传工具。目标平台 Windows / Android(已发布)、Linux(已验证)/ macOS / 鸿蒙(规划)。当前独立版本线 **0.1.x**,最新正式版 **v0.1.1**(用户已验收)。

- 仓库:`https://github.com/sunmerx/AnyShare`(fork 自 localsend/localsend)
- 本地:`E:\code\AnyShare`,分支 **`anyshare` = 开发与发布线 = GitHub 默认分支**;`main` 为其同步镜像;`upstream` 指向 localsend/localsend
- 用户角色:产品决策者 + 验收者;Agent 角色:全部编码/构建/发布

## 4. 发布流程(实测可复现)

1. **版本号六处一致**(CI 强校验):`app/pubspec.yaml`、`support/scripts/compile_windows_exe-inno.iss`、`cli/Cargo.toml`、`support/build/msix/content/AppxManifest.xml`(x.0.0 尾缀)、`support/build/appimage/AppImageBuilder_{x86_64,arm_64}.yml`、issue 模板 placeholder
2. 本地构建:`flutter build windows --release` + `flutter build apk --release`
3. 组装载荷:`D:\inno` ← `build\windows\x64\runner\Release\*` + `app\assets\packaging\logo.ico`
4. 安装器:`ISCC.exe /DSkipSignTool /DSkipMsixHelper support\scripts\compile_windows_exe-inno.iss` → `D:\inno-result\AnyShare.exe`(重命名带版本)
5. 便携版:python zipfile 打包 `D:\inno`
6. 发布:**分步**——`gh release create v0.1.x`(先建空 release+notes)→ **逐个** `gh release upload`(批量传大文件会 408 整体回滚)
7. CI 构建类 workflow 均为 **workflow_dispatch 手动触发**:`gh workflow run <name> --ref anyshare -R sunmerx/AnyShare`

## 5. CI 特性与怪癖(重要)

- **fork 上 push 不触发 workflows**(即使 active)——一切构建/检查靠 `gh workflow run` 手动 dispatch
- `build_windows_exe.yml`(签名版)依赖 LocalSend 作者的 Azure Trusted Signing,**fork 不可用**;发布走 `build_windows_exe_unsigned.yml`
- Android 签名 steps 已条件化(无 secrets 跳过;`build.gradle` 无 key.properties 回退 debug 签名)
- `ci.yml` 已加 workflow_dispatch;版权一致性检查要求三处(Runner.rc/cli build.rs/macOS xcconfig)字符串完全一致,现值 `Copyright (C) 2022-2026 Tien Do Nam, 2026 AnyShare Dev`
- MSIX helper 是 LocalSend 专属特性,AnyShare 不构建(CMake 条件安装,iss 用 SkipMsixHelper)

## 6. 架构速览(读这些再动代码)

- 上游架构:`AGENTS.md`(必读)+ `docs/上游代码研读.md`
- HTTP 服务器/发现 = Rust(packages/core),**动 Rust 会增加 rebase 成本——AnyShare 扩展全部做在 Dart 层**
- **信任模型**:`app/lib/util/trust_evaluator.dart`(纯函数判定链)+ `trust_provider.dart`(用量账本 ls_trust_usage)+ `favorite_device.dart`(TrustLevel/QuotaMode 字段)
- **配对/扩展协议**:`docs/扩展协议设计.md`(设计)+ `app/lib/provider/network/extension_server_provider.dart`(53318 端口:capabilities/pair/register、pair/confirm、trust/query;限速 5/min;确认门 userGate)+ `pairing_provider.dart`(发起方)+ `app/lib/util/sas.dart`(X25519+HKDF+6位码)
- **接收确认挂点**:`receive_controller.dart` onPrepareUpload(信任判定链+拒绝 toast)
- **发送前提示**:`send_provider.dart` `_showTrustHint`(fire-and-forget /trust/query)
- 持久化:shared_preferences,键前缀 `ls_*`(`persistence_provider.dart`;有 getStringList 容错)
- 状态管理 **Refena**(非 Riverpod):计算型用 `ViewProvider`(plain Provider 不支持 watch);动作模式见 favorites_provider.dart

## 7. 现行产品语义(用户裁决,勿回退)

1. **配对** = 接收方一次性确认(SAS 6 位码双屏比对;发起方零操作;被配对方点「码一致」);配对成功默认落 `temp` 信任
2. **传输确认**:发送方永不操作;接收方对 **temp/limited** 传输点击确认;**full 免点击自动接收**;limited 限额超限自动拒(静默+接收方 toast);blocked 自动拒;未知设备走上游原确认流
3. **传输完成免点击**:autoFinish 默认**开**(完成页 3 秒倒计时自动关页);系统级完成通知 = 可选后续(需通知插件)
4. 发送前提示条(/trust/query):告知"将自动接收/设有限额/已拉黑"
5. 图标保持原版(LocalSend 形状青色换色版)——用户否决过重绘,**改视觉前先出小样确认**

## 9. 已知坑(踩过的)

- Git Bash heredoc 会吃反斜杠层(python 脚本用 `chr(92)` 构造路径;长内容用 Write 工具写脚本文件再执行)
- `dart format` 会挪行内 `// ignore:` 位置 → 用 `unawaited()` 替代;**提交前必跑 format**(CI format 检查会挂)
- refena:plain `Provider` 无 watch;StatelessWidget 不能混 Refena mixin(用 `context.ref`);init() 里不可 dispatch 同 provider(递归栈溢出)
- flutter_test binding 会拦截进程内 HttpClient(全 400)→ 测 HTTP 服务用 InMemory prefs store + 不 ensureInitialized
- GitHub fork:push 不触发 workflows;gh release 批量传大文件 408 回滚 → 分步
- Windows:exe 被占用导致 LINK1104(先 taskkill);`taskkill //IM`(双斜杠);CLI 高频掉线(OPPO ColorOS),安装 fallback=手机浏览器直下 release APK
- 模拟器后台任务勿接 head 管道(SIGPIPE 杀进程);宿主机地址 10.0.2.2
